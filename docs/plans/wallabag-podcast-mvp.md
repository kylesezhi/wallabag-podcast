## Idea
A single-user, self-hosted Python+FastAPI web app that converts Wallabag saved articles into a podcast RSS feed using Kokoro-FastAPI for TTS. Core workflow: fetch N random unread articles (excluding configured tags) into an editable queue; user removes unwanted ones; Generate synthesizes one MP3 episode per article with a spoken title intro (`[pause:0.5s] <title> [pause:1s] <body>`); episodes are served via a podcast RSS feed (no auth, local network). Secrets in .env; tunables (articles per drive, voice) in UI/SQLite. No scheduler in v1 (manual only); automation UI is disabled/coming-soon. Queue state machine: staged -> generating -> done|failed; done -> archived. Local processed_articles index dedupes so no article is re-picked. No Wallabag state mutation. See linked specs (architecture-and-stack, data-model, config-and-env) for the full contract.

## Implementation
- Scaffold project: pyproject.toml (deps: fastapi, uvicorn, httpx, beautifulsoup4, lxml, mutagen, feedgen, jinja2, pydantic-settings, python-multipart), app/ package, .env.example, config.py (pydantic-settings reading the config-and-env spec), db.py schema init from the data-model spec, data/ gitignored, README skeleton. Acceptance: `uv sync && uvicorn app.main:app` imports clean and creates data/podcast.db on startup.
- Wallabag client (app/wallabag.py): WallabagClient with OAuth password-grant, in-memory token cache + automatic refresh on 401; list_unread_metadata() paginated (archive=0, detail=metadata) honoring MAX_FETCH_PAGES; get_entry(id) returning full content. Use httpx AsyncClient. Tests with httpx MockTransport covering token, refresh, pagination, and tag-excluded filtering. Acceptance: pytest tests pass; client returns parsed entry dicts matching the Wallabag shape (id, title, content, domain_name, reading_time, language, tags[], url).
- Text cleaning pipeline (app/textclean.py): BeautifulSoup4+lxml to strip script/style/nav/footer/aside/figure/img/form; extract text from p/h1-6/li/blockquote/pre; decode entities; normalize whitespace; remove boilerplate/related-articles/footer regex; ensure terminal punctuation per sentence; assemble TTS input `[pause:0.5s] {clean_title} [pause:1s] {clean_body}`; skip-if-too-short guard (< MIN_TEXT_CHARS raises a SkipArticle error). Tests against fixtures of real Wallabag HTML content. Acceptance: tests assert no HTML tags/entities remain, no bare URLs, intro string format exact, skip guard triggers on a short fixture.
- Kokoro client + episode generation core (app/kokoro.py, app/pipeline.py generate flow): KokoroClient.voices() from GET /v1/audio/voices; .synthesize(text, voice, speed) streaming POST to /v1/audio/speech (model=kokoro, response_format=mp3) writing to data/audio/{id}.mp3. measure_duration() via mutagen. pipeline.generate_all(): for each staged episode -> status=generating -> clean text -> synthesize -> set duration_sec/audio_path -> status=done + insert processed_articles; on failure status=failed + error; continue past failures. Tests with mocked Kokoro transport. Acceptance: tests show staged->done transitions, audio file written, duration set, one processed_articles row per success, a failing article is marked failed while others still succeed.
- Selection + queue ops (app/pipeline.py): add_random(n) (enumerate unread metadata, client-side exclude EXCLUDE_TAGS, exclude wallabag_ids in processed_articles or already staged/done, pick n random, insert staged with est_minutes=reading_time), remove_item(id) for staged|failed, archive_completed(), clear_queue() (staged|failed only), stats(). Idempotency on wallabag_id. Tests cover tag exclusion, dedupe, randomness seedability, and all ops. Acceptance: tests assert no excluded-tag article is ever staged, no already-processed id re-staged, remove/archive/clear produce correct state, stats sums are correct.
- RSS feed (app/rss.py + GET /feed.xml route in main.py): build podcast RSS 2.0 with feedgen + iTunes extensions from done, non-archived episodes (newest first); enclosure url = f'{BASE_URL}/audio/{id}.mp3', length = file size bytes, type=audio/mpeg; pubDate = generated_at; channel title/author from env. Tests assert valid RSS structure, enclosure correctness, archived episodes excluded. Acceptance: feed validates as a podcast feed; a sample <item> has correct enclosure/url/length/type.
- Web UI (templates/ + static/): Jinja2 server-rendered, mobile-responsive, matching reference/mockup.png (cream/green/tan, coffee branding, 'Today's Drive' card with status + minutes/articles stats, 'Generate' + 'Add Random' buttons, Queue list with per-item remove ⊖ + status, 'Archive Completed' + 'Clear Queue' bulk buttons, progress polling during generation via HTMX/fetch). Settings page: Wallabag connection status (read-only) + Test button, tunables (articles_per_drive, voice dropdown from Kokoro voices, Save), automation toggle disabled 'coming soon'. Routes in main.py: GET / (home), GET /settings, POST /queue/add-random, POST /queue/{id}/remove, POST /queue/generate, POST /queue/archive-completed, POST /queue/clear, GET /queue/status (polling), POST /settings (save), GET /wallabag/test. Acceptance: manual click-through reproduces the mockup flow; generation shows live progress; settings persist across restarts.
- Audio serving + integration + compose + README: range-aware GET /audio/{id}.mp3 (HTTP 206 for podcast seeking), wire all routes + static + lifespan in main.py, end-to-end manual test against a running Kokoro container (test-kokoro docker) and a real/seeded Wallabag, complete .env.example, add docker-compose.yml (app + ghcr.io/remsky/kokoro-fastapi-cpu:latest), write README with setup, .env, BASE_URL-for-phone note, and podcast-app subscription steps. Acceptance: full flow works end-to-end (add random -> edit -> generate -> subscribe feed in a podcast app -> play with seek); docker compose up starts both services; README has reproducible setup steps.
