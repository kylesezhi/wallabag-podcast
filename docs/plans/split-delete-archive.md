## Idea
Split the single per-episode Delete button (which atomically archives-in-Wallabag + deletes-from-podcast) into two independent buttons: "Delete" (podcast cleanup only — removes episode row/RSS entry, unlinks mp3 for done, removes processed_articles dedupe row so the article is re-pickable; does NOT touch Wallabag, article stays unread) and "Archive" (Wallabag mark-read only — PATCH archive=1; does NOT delete anything locally, episode stays in podcast). Both render on staged|failed|done|generating side-by-side. The styled confirmation modal guards both with distinct copy and a per-action confirm label (existing data-confirm-label mechanism; no JS change). Stop behavior preserved: Delete on a generating episode during an active run triggers task.cancel() (the loop owns the row); Archive on a generating episode just archives (no conflict). delete_item becomes sync (no I/O), archive_item is async. ValueError contract preserved for both; WallabagError handling moves entirely to the archive path. The delete-archives-wallabag feature is superseded. See spec split-delete-archive for the full contract.
